8. Loss Function Mismatch
Ensure your model's final layer does not include a softmax. nn.CrossEntropyLoss applies softmax internally. If your model outputs probabilities (e.g., from a softmax), the loss will be computed on probabilities, leading to vanishing gradients. In your TensorFlow model, final layer had activation='softmax' but you used sparse_categorical_crossentropy which also expects logits by default? Actually, in TF with from_logits=False (default), the loss expects probabilities. In TF, you have softmax and loss with from_logits=False, so it's correct. In PyTorch, you must remove softmax from the model.

Check your model definition in src.models – if it includes nn.Softmax(dim=1) at the end, remove it.

9. Early Stopping / Best Model Loading
You're saving and loading the best model state. Ensure that after loading, you set model.eval() for evaluation. But that shouldn't affect final test accuracy if you evaluate after loading.

🧪 Quick Minimal Test
Replace the complicated training with a minimal script to isolate the issue:

python
# Minimal test – use a tiny subset, simple SGD
model = create_cnn_baseline(activation='relu')
model.to(device)
criterion = nn.CrossEntropyLoss()
optimizer = optim.SGD(model.parameters(), lr=0.01)

# Use only first 1000 samples
subset = torch.utils.data.Subset(train_dataset, range(1000))
loader = DataLoader(subset, batch_size=64, shuffle=True)

for epoch in range(5):
    model.train()
    total_loss = 0
    for images, labels in loader:
        images, labels = images.to(device), labels.to(device)
        optimizer.zero_grad()
        outputs = model(images)
        loss = criterion(outputs, labels)
        loss.backward()
        optimizer.step()
        total_loss += loss.item()
    print(f"Epoch {epoch}: Loss = {total_loss/len(loader):.4f}")
If loss decreases nicely (e.g., from ~2.3 to <0.5), then the model and data pipeline are fine. If loss stays high (~2.3), the model is not learning – likely a gradient issue.

📌 Most Likely Culprits
Model output includes softmax – causing CrossEntropyLoss to receive probabilities, not logits.

Incorrect implementation of custom activation layers – check their forward pass and parameter shapes.

Data not normalized correctly – maybe images are still 0-255 (though you divide by 255).

BatchNorm behavior – ensure model.train() and model.eval() are used appropriately; BN running stats might be off.
